## P5.2 阶段

### 目标

完善 AI Agent 聊天的 Skill 权限拒绝链路，并统一 `domain_and_skill_binding` 的赋值位置，减少前后端和 focus_context 内重复写死。

### 完成内容

1. **统一 Agent Kernel 绑定参数**
   - 前端 Agent 请求不再固定传 `domainAndSkillBinding`。
   - 后端在 `AiAgentService.BuildKernelRequest` 中统一解析最终 `domain_and_skill_binding`。
   - 后端将同一个绑定值同步写入 Kernel 顶层参数和 `context.focus_context.domain_and_skill_binding`，节点/全图/全局 focus_context 不再各自写死。

2. **Skill 拒绝原因传递**
   - 前端点击「拒绝」时弹出原因输入框，允许填写拒绝原因。
   - 拒绝确认请求新增 `confirmedSkillCalls[].reject_reason`。
   - 本地 Skill 卡片状态同步显示 `permission.reject_reason`、`execution.denied_reason` 和包含原因的错误文案。

3. **拒绝原因兼容别名**
   - 后端转发 `confirmed_skill_calls` 前会归一化拒绝原因。
   - 当调用方传入 `denied_reason`、`deny_reason` 或 `reason`，且未传 `reject_reason` 时，后端会补齐标准字段 `reject_reason`。
   - 旧调用方仅传 `{ call_id, approved: false }` 仍保持原流程。

4. **Agent 非最终输出渲染**
   - 前端将 `status` 非 `final` 且非 `error` 的 Agent 返回识别为中间进度。
   - `waiting_permission` 等中间态的 `main_text` 会渲染为「Agent 进度」，用于表达 AI 思考或当前推进状态。
   - 后端不再把非最终空正文补成“Agent 未返回正文”，避免中间态被误判为最终回复。

## P5.1 阶段

### 目标

实现六种聊天方式中的「全图问答（Agent）」和「全局问答（Agent）」，继续复用 P5.0 的 AgentBuild AI Agent 内核调用层，仅按模式切换请求参数、focus_context 和 Agent 身份提示。

### 完成内容

1. **全图问答 Agent 后端端点**
   - 新增 `POST /api/ai/map-agent-chat`。
   - 请求包含当前导图 ID、用户消息、对话上下文、AgentBuild 路径、`confirmedSkillCalls`、`historySkillCalls` 和全局模型配置。
   - 后端校验导图存在后，将导图基础信息、全量节点 `nodes`、全量关联 `relations`、统计信息和对话历史传入 Agent Kernel 的 `focus_context`。

2. **全局问答 Agent 后端端点**
   - 新增 `POST /api/ai/global-agent-chat`。
   - 全局问答复用 AgentBuild 调用和权限确认流程，但 `focus_context` 只包含 NetMind 基础信息、对话历史、Agent 记忆和上下文预算。
   - 按 P5.1 要求，全局问答不传递任何节点、关联或思维导图数据。

3. **Agent 场景配置扩展**
   - `AiAgentOptions` 新增 `MapQuestion` 和 `GlobalQuestion`。
   - 全图/全局/节点 Agent 的 `Identity` / `Cues` 文本迁移到 `src/NetMind.WebApi/Config/AiCleanPrompts/*-agent-*.prompt.md`，`appsettings.json` / `appsettings.Development.json` 仅保存 Prompt 文件路径。
   - `AiAgentService` 将 P5.0 节点 Agent 流程整理为通用 `ChatWithAgentAsync`，三种 Agent 模式共享模型解析、上下文预算、AgentBuild 子进程调用和返回映射。

4. **AgentBuild 传入参数适配**
   - 重读 `AgentKernel接口规范.md` 后，按当前 AgentBuild 入参补充 `skill_runtime`。
   - `skill_runtime` 由 NetMind 后端注入，不进入 Prompt，只在 Kernel 执行 Skill 时进入 `params.__runtime`。
   - 新增 `App:BaseUrl` 和 `AiAgent:SkillRuntimeTimeoutSeconds` 配置，默认传入 WebAPI 地址、Skill 通用超时和常用 API endpoint 映射。
   - `Program.cs` 默认监听地址改为读取 `App:BaseUrl`，不再在代码中写死本地 URL。

5. **前端模式启用**
   - AI 浮窗启用「全图问答（Agent）」和「全局问答（Agent）」。
   - `useNodeAiChat.js` 新增 `map-agent` / `global` 端点路由、会话前缀、上下文要求判断和 Skill 权限确认复用逻辑。
   - 全图 Agent 要求当前导图 ID；全局 Agent 不要求节点或导图。

6. **文档与帮助说明**
   - 更新 `AI大模型配置说明.md`，补充 P5.1 两个 Agent 模式的端点、上下文范围和配置结构。
   - 更新 `项目结构速查.md` 与内置应用帮助说明，标记已实现模式。

## P5.0 阶段

### 目标

实现六种聊天方式中的「节点问答（Agent）」，通过 NetMind 后端调用外部 AgentBuild AI Agent 内核脚本，并为后续其他 Agent 模式预留通用调用入口。

### 完成内容

1. **AgentBuild 通用调用层**
   - 新增 `IAiAgentService` / `AiAgentService`，统一负责 AgentBuild 根目录解析、Python 子进程调用、stdin/stdout JSON 交互、超时控制和日志记录。
   - 后端通过 `python -m src.agent_kernel` 等价方式调用 AgentBuild；默认 `PythonExecutable=py`，避免本机 `python` 不在 PATH 时无法运行。
   - 支持将 AgentBuild 返回的 `status`、`agent_target`、`main_text`、`skill_calls`、`context_update` 原样映射给前端。

2. **节点问答 Agent 后端端点**
   - 新增 `POST /api/ai/node-agent-chat`。
   - 请求包含当前节点 ID、用户消息、对话上下文、AgentBuild 路径、`confirmedSkillCalls`、`historySkillCalls` 和全局模型配置。
   - 后端加载当前节点、父节点链、子节点和关联节点，组装为 Agent Kernel 的 `focus_context`。
   - `domain_and_skill_binding` 当前固定使用 `default`。

3. **Agent 配置**
   - 新增 `AiAgentOptions`，配置项位于 `appsettings.json` / `appsettings.Development.json` 的 `AiAgent` 节点。
   - 节点问答 Agent 的 `IdentityLines` 和 `CuesLines` 写入配置文件，满足 Prompt 不硬编码要求。
   - 全局默认 AI 模型会转换为 AgentBuild 的 `model_config`，并由后端注入 API Key。

4. **前端节点 Agent 模式**
   - 设置弹窗新增「AgentBuild 脚本设置」，将 AgentBuild 根目录保存在 localStorage。
   - AI 浮窗启用「节点问答（Agent）」模式。
   - `useNodeAiChat.js` 新增 Agent 上下文、Skill 调用历史和权限确认状态管理。
   - 前端展示 Agent Skill 调用记录；当状态为 `waiting_permission` 时展示「允许 / 拒绝」按钮，并把确认结果带回后端继续执行。

5. **文档更新**
   - 更新 `AI大模型配置说明.md`，记录 AgentBuild 配置、端点、模型约束和权限交互。
   - 更新 `项目结构速查.md` 和 `总开发进度.md`。

6. **权限确认交互修复**
   - 修复 Agent Skill 权限确认后旧卡片仍保持可点击状态的问题。
   - 点击「允许 / 拒绝」后立即将本地 Skill 状态锁定为「已允许 / 已拒绝」，隐藏权限按钮，避免重复发送同一个确认请求。
