## 总进度

当前项目已完成 P0 数据闭环 Demo、P1 基础结构化能力、P2 可用产品形态和 P3 知识图谱化与产品补强。P0 建立了 .NET WebAPI、Vue3 前端、PostgreSQL 表结构和导图/节点/关联的最小 CRUD 闭环。P1 在此基础上补齐完整导图导入导出、AI 清洗、真实模型配置、上下文需求澄清、中文本土化、接口日志、AI API 日志、存储层写操作日志和 AI 对话记录表。P2 将前端从 Demo 页面推进到可用产品形态，完成主工作台重构、Canvas 思维导图、图上编辑、知识卡片、关联图谱、响应式优化和节点排序校验。P3 完成敏感配置治理、Prompt 外置、节点链接式关联、跨图跳转、全局搜索、历史对话入口、节点坐标保存和删除导图链路完善。P3.3 进行项目收尾，补齐安装包封装建议、AI Agent 阶段规划和仓库忽略规则，确保后续进入 P4 时能快速定位代码、接口、部署步骤和历史决策。

## P1 阶段收尾摘要

P1 已从“手动维护导图”推进到“AI 生成标准结构，用户确认后进入导图数据层”。核心成果包括：`netmind.mindmap.v1` 导入导出结构、DeepSeek/Ollama 配置化调用、上下文压缩与需求澄清对话、AI 对话记录落库、前后端中文化、日志文件输出和接口/存储/AI 调用日志。当前限制是本地环境未完整覆盖真实 PostgreSQL 与外部模型冒烟，P2 前建议先执行 SQL 迁移并补一轮真实环境验证。

## P2 阶段收尾摘要

P2 已完成“可用产品形态”的主要目标。前端引入 Element Plus 并拆分为页面、组件、组合逻辑和 API 服务边界；主页面形成展示/工作台与图/列表两组视图模型；Canvas 思维导图支持节点绘制、父子连线、关联虚线、拖拽平移、滚轮缩放、节点拖动和工作台图上编辑；知识卡片支持 Markdown 展示，并内嵌两层关联图谱；新增导图页面集中承载 AI 清洗、需求对话和导入导出；后端更新节点时补充同级排序重复校验。

P2 收尾补齐根目录 `readme.md`、`AI文档/部署文档.md`，并更新项目结构速查。当前已知限制是项目健康检查展示数据曾停留在旧阶段，如后续需要对外展示真实阶段状态，应单独同步检查。

## P4 阶段规划摘要

P4 建议调整为 AI Agent 基础建设阶段，不直接开做具体 AI Agent 功能模块。核心目标是先把稳定运行所需的底层能力搭起来：

- 上下文管理：按节点、当前导图、全库只读、软件操作四种范围组装上下文，并建立 token 预算、摘要压缩和来源引用规则。
- 工具调用引擎：建立白名单工具、权限矩阵、参数校验、失败重试和人工确认机制，区分只读工具与写入工具。
- 对话状态管理：在现有 AI 对话记录基础上补充请求类型、上下文范围、工具轨迹、确认状态和恢复能力。
- 可观测性：记录 requestId、模型调用、工具调用、耗时、失败原因和上下文摘要，支持后续调试多轮对话。

## P5 阶段规划摘要

原 P4“AI 增强交互”和 P5“全局知识 AI”建议合并为新的 P5“AI Agent 功能模块”。功能按上下文范围划分为四类：

| 功能模块 | 范围 | 权限策略 |
| --- | --- | --- |
| 节点聚焦辅助 | 当前节点、父子节点、直接关联节点 | 可生成编辑建议，写入前必须用户确认 |
| 思维导图全局辅助 | 当前导图全量结构与摘要 | 可生成批量整理方案，实际修改走受控工具 |
| 数据库全局只读问答 | 全库导图、节点、关联和语义检索结果 | 只读问答，不允许写入 |
| 软件操作问答 | 当前页面状态、帮助文档和接口能力 | 只读解释与操作指引，不读取无关业务数据 |

P5 的实施顺序建议从“数据库全局只读问答”和“软件操作问答”开始，因为权限风险最低；再进入节点聚焦辅助；最后做导图全局辅助和批量修改。
