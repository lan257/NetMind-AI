# 阶段开发与人工验收细化模板

## 1. 使用方式（给 AI Agent 的固定指令骨架）

每次仅下发一个子阶段任务，使用以下模板：

```md
【阶段】P?.?
【目标】一句话描述本子阶段目标
【范围内】允许修改的模块/文件
【范围外】明确禁止改动的模块/能力
【输入】已有文档、接口、数据样例
【输出】代码、脚本、测试、文档清单
【完成定义 DoD】量化验收标准
【人工审核点】我需要人工确认的点
【提交要求】分支名、commit 规范、PR 说明
```

---

## 2. 子阶段通用门禁（每个子阶段都必须满足）

1. 编译通过：`dotnet build` 通过。
2. 自动化测试通过：本子阶段相关测试 100% 通过。
3. 文档同步：接口/数据结构变更必须同步到文档。
4. 可回滚：提供“回滚步骤”或“回滚 commit”说明。
5. 人工验收通过：你勾选人工检查清单后才可进入下一子阶段。

---

## 3. 人工审核清单（每次评审都用）

1. 功能是否只覆盖本子阶段范围（无越界开发）。
2. 是否有破坏已有流程（回归冒烟是否通过）。
3. 接口入参/出参与文档是否一致。
4. 错误处理是否符合预期（空值、异常、超时、非法输入）。
5. 数据写入是否正确（新增、修改、删除、幂等）。
6. 前端交互是否可用（主路径可走通）。
7. 日志是否可定位问题（关键路径有日志/错误码）。
8. 性能是否在可接受范围（至少无明显卡顿或超时）。

---

## 4. 分阶段细化（P0~P6 拆分为可审核小阶段）

## P0 数据闭环 Demo（手动创建 + 存储 + 展示）

### P0.1 工程脚手架与约束落地
- 目标：建立“后端分层 + 前端空壳 + 仓库规范”三位一体的最小可运行基线。
- 范围内：
  - 初始化后端解决方案与分层项目（API/Application/Domain/Infrastructure/Contracts）。
  - 初始化前端 Vue3 + TypeScript 空壳工程。
  - 落地仓库级工程约束（SDK 固定、代码风格、忽略规则、基础健康检查）。
- 范围外：
  - 业务功能开发（CRUD、AI、数据库迁移）。
  - UI/交互细节打磨与权限体系。
- 输出（本阶段产物）：
  - `src/backend/NetMind.sln`
  - `src/backend/NetMind.Api`、`src/backend/NetMind.Application`、`src/backend/NetMind.Domain`、`src/backend/NetMind.Infrastructure`、`src/backend/NetMind.Contracts`
  - `src/frontend/netmind-web`
  - `.editorconfig`、`.gitignore`、`Directory.Build.props`、`global.json`
- DoD：
  - 解决方案完成分层与引用约束（依赖方向：API -> Application -> Domain，Infrastructure 仅通过 Application/Domain 被 API 组合）。
  - 后端可启动并提供健康检查端点 `/healthz`。
  - 前端工程可执行 `npm run dev` 启动空壳页面（需先 `npm install`）。
  - 根目录执行 `dotnet build src/backend/NetMind.sln` 通过。
  - 脚手架提交后可作为 P0.2~P0.6 的统一开发基线。
- 人工审核点：
  - 目录是否清晰体现前后端边界与后端分层边界。
  - 是否不存在“跨层直接引用”与“业务代码提前耦合”。
  - 新成员是否可按文档在 15 分钟内完成本地启动。

### P0.2 数据库最小模型与迁移
- 目标：落地 `mind_map`、`node`、`node_relation` 最小表结构。
- 输出：建表脚本、索引、初始化数据脚本。
- DoD：
  - 三张表可成功创建。
  - 主键/外键/必要索引生效。
  - 提供 3 组插入样例数据。

### P0.3 后端最小 CRUD API
- 目标：支持思维导图与节点增删改查。
- 输出：Controller/Service/Repository/DTO。
- DoD：
  - 至少 8 个核心接口（图/节点 CRUD）。
  - Swagger 可调通。
  - 核心接口单测或集成测试通过。

### P0.4 前端最小可视化展示
- 目标：实现“创建图 -> 新增节点 -> 展示节点列表/简单关系”。
- 输出：最小页面与 API 对接。
- DoD：
  - 主流程端到端可走通。
  - 出错时有明确提示。

### P0.5 闭环联调与冒烟测试
- 目标：验证最小业务闭环稳定可用。
- 输出：冒烟用例与结果记录。
- DoD：
  - 至少 10 条冒烟用例全部通过。
  - 明确已知问题清单（如有）。

### P0.6 人工验收与基线冻结
- 目标：冻结 P0 基线，进入 P1。
- 输出：验收记录、风险清单、回滚方案。
- DoD：
  - 你人工签字通过。
  - 打基线 tag（如 `v0.1.0-p0`）。

## P1 基础结构化能力（AI -> 结构化数据 -> 用户确认）

### P1.1 输入管道（文本/文档）标准化
- DoD：输入被统一为内部标准文本结构；异常输入可拦截。

### P1.2 AI 结构化解析 V1
- DoD：输出统一 JSON（节点、关系、置信度、来源片段）。

### P1.3 结构校验器 V1（规则引擎）
- DoD：可识别必填缺失、重复节点、非法关系、孤立节点。

### P1.4 AI 二次修正回路
- DoD：校验失败可自动触发修正，最多 N 次重试可配置。

### P1.5 用户确认与手动修订页
- DoD：用户可编辑、拒绝、确认结构化结果后再入库。

### P1.6 入库与可追溯记录
- DoD：保存原文、解析结果、修订记录、最终入库版本。

### P1.7 P1 验收冻结
- DoD：结构化链路端到端可跑通并通过人工抽检。

## 6. 建议节奏（便于及时人工审核）

1. 单个子阶段控制在 0.5~2 天内完成。
2. 每完成 1 个子阶段就人工验收，不跨子阶段合并。
3. 每 3 个子阶段做一次小里程碑复盘（范围、质量、进度）。
