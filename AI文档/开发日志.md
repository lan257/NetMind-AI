## 2026-04-28 P0.2 落地数据库搭建最小表结构

### 本阶段目标

- 根据 `/AI文档/项目研发说明.md` 中的数据库结构参考，落地 PostgreSQL 最小建表脚本。
- 覆盖最小闭环表：`mind_map`、`node`、`node_relation`、`node_meta`。
- 提供主键、外键、必要索引和 3 组样例数据。

### 完成内容

- 新增 `/AI文档/SQL/Init.sql`。
- 建立四张 PostgreSQL 表：
  - `mind_map`：思维导图主表，包含标题、根节点、创建/更新时间。
  - `node`：节点表，包含所属导图、父节点、标题、内容、同级排序、创建/更新时间。
  - `node_relation`：节点关系表，包含起点、终点、关系类型、权重、所属导图、创建时间。
  - `node_meta`：节点元数据表，使用 `(node_id, key)` 复合主键保存扩展属性。
- 建立主键与外键：
  - `node.map_id -> mind_map.id`
  - `node.parent_id -> node.id`
  - `node_relation.source_id -> node.id`
  - `node_relation.target_id -> node.id`
  - `node_relation.map_id -> mind_map.id`
  - `mind_map.root_node_id -> node.id`
  - `node_meta.node_id -> node.id`
- 建立必要索引：
  - `node.map_id`
  - `node.parent_id`
  - `node(map_id, parent_id, order_no)`
  - `node` 标题/内容全文检索 GIN 表达式索引
  - `node_relation.source_id`
  - `node_relation.target_id`
  - `node_relation.relation_type`
  - `node_relation.map_id`
  - `node_relation(map_id, relation_type)`
  - `node_meta.key`
- 初始化 3 组样例数据：
  - 产品需求知识图谱
  - 技术方案知识图谱
  - 项目计划知识图谱
- 为样例节点补充 3 条 `node_meta` 元数据。

### 脚本幂等与安全性

- 表结构使用 `CREATE TABLE IF NOT EXISTS`。
- 索引使用 `CREATE INDEX IF NOT EXISTS`。
- 循环外键 `mind_map.root_node_id -> node.id` 使用条件 `DO` 块追加，避免重复执行时报错。
- 初始化数据使用固定 ID 与 `ON CONFLICT ... DO UPDATE`，脚本可重复执行。
- 显式执行 `setval`，保证手动插入样例数据后 identity 序列继续可用。
- 样例数据先插入 `mind_map`，再插入 `node`，再回填 `root_node_id`，最后插入 `node_relation` 和 `node_meta`，避免外键插入顺序失败。

### 验证结果

- 已静态检查 `/AI文档/SQL/Init.sql`，确认包含四张表、主键、外键、必要索引和 3 组样例数据。
- 当前机器未安装 `psql` 命令，无法在本机直接连接 PostgreSQL 执行建表验证。

### 说明

- 全文索引使用 PostgreSQL `to_tsvector('simple', ...)` 表达式索引，满足 P0 阶段最小检索能力，后续可根据中文分词方案再升级。

## 2026-04-28 P0.3 支持思维导图与节点增删改查

### 本阶段目标

- 支持思维导图、节点、节点关联的核心增删改查接口。
- 删除统一采用逻辑删除。
- 按人工审核点提供导图、节点、节点关联的成对删除能力。
- 提供 Swagger/OpenAPI 入口和核心集成测试。

### 完成内容

- 新增 DTO：
  - `MindMapDto`、`CreateMindMapRequest`、`UpdateMindMapRequest`
  - `NodeDto`、`CreateNodeRequest`、`UpdateNodeRequest`
  - `NodeRelationDto`、`CreateNodeRelationRequest`、`UpdateNodeRelationRequest`
  - `DeleteResultDto`
- 新增实体模型：
  - `MindMapEntity`
  - `NodeEntity`
  - `NodeRelationEntity`
  - `NodeMetaEntity`
- 新增 Repository/Service/Controller 分层：
  - `IMindMapRepository` / `MindMapRepository`
  - `INodeRepository` / `NodeRepository`
  - `INodeRelationRepository` / `NodeRelationRepository`
  - `IMindMapService` / `MindMapService`
  - `INodeService` / `NodeService`
  - `INodeRelationService` / `NodeRelationService`
  - `MindMapsController`
  - `NodesController`
  - `NodeRelationsController`
- 当前 P0.3 使用内存 Repository 承载接口行为，保留 Repository 边界，后续接入 PostgreSQL 时可替换实现。
- 新增手写 OpenAPI/Swagger 入口：
  - `GET /swagger`
  - `GET /swagger/index.html`
  - `GET /swagger/v1/swagger.json`
- 新增无第三方依赖集成测试项目：
  - `/src/NetMind.IntegrationTests`

### 核心接口清单

- 思维导图：
  - `GET /api/mind-maps`
  - `GET /api/mind-maps/{id}`
  - `POST /api/mind-maps`
  - `PUT /api/mind-maps/{id}`
  - `DELETE /api/mind-maps/{id}`：仅逻辑删除导图本身。
  - `DELETE /api/mind-maps/{id}/cascade`：逻辑删除导图及其节点、节点关联。
- 节点：
  - `GET /api/nodes/by-map/{mapId}`
  - `GET /api/nodes/{id}`
  - `POST /api/nodes`
  - `PUT /api/nodes/{id}`
  - `DELETE /api/nodes/{id}`：逻辑删除节点本身，保留子节点并提升到原父级。
  - `DELETE /api/nodes/{id}/subtree`：逻辑删除节点本身及其子树。
- 节点关联：
  - `GET /api/node-relations/by-map/{mapId}`
  - `GET /api/node-relations/{id}`
  - `POST /api/node-relations`
  - `PUT /api/node-relations/{id}`
  - `DELETE /api/node-relations/{id}`：逻辑删除单条节点关联。
  - `DELETE /api/node-relations/by-node/{nodeId}`：逻辑删除与节点相关的全部关联。

### SQL 变更

- 更新 `/AI文档/SQL/Init.sql`：
  - `mind_map`、`node`、`node_relation` 新增 `is_deleted`、`deleted_at` 字段。
  - 查询索引调整为带 `is_deleted = FALSE` 的部分索引。
- 新增 `/AI文档/SQL/P0.3_AddLogicalDelete.sql`：
  - 为已有 P0.2 数据库安全追加逻辑删除字段。
  - 为未删除数据追加必要部分索引。
  - 脚本使用 `ADD COLUMN IF NOT EXISTS` 和 `CREATE INDEX IF NOT EXISTS`，可重复执行。

- 已执行 `dotnet run --project src/NetMind.IntegrationTests/NetMind.IntegrationTests.csproj --no-build`，通过。
